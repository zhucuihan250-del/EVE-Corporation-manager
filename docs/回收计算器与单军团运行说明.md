# 回收计算器与单军团运行说明

## 管理员首次启用

在管理区打开“回收管理”。首次上线默认允许回收全部类别，但计算器暂未开放，必须由管理员或总监确认计价规则后开启。

1. 选择默认价格基准：吉他最高买价、吉他最低卖价、买卖中间价或固定单价。
2. 设置回收比例。例如 90 表示参考单价的 90%，不是扣除 90%。固定单价也会乘以回收比例；希望按所填固定价直接回收时填 100%。
3. 设置报价有效期，开启回收功能并保存。
4. 如需限制范围，添加类别或单品规则。也可以关闭默认回收，再逐项开放。

规则逐字段继承，优先级是：单品规则 > 类别规则 > 全局设置。比如禁止一个类别、再允许其中一个物品，该物品仍可回收；其价格、比例没有单独填写时继续继承。删除覆盖规则意味着恢复继承，不是禁止该物品。

两名管理员同时编辑时，较旧版本的保存会被拒绝；刷新后确认最新配置再保存，避免覆盖他人的修改。

## 成员报价

打开“回收计算器”，将游戏内复制的物品清单粘贴进去。建议保留制表符分隔的名称、数量列；也可以每行一个完整物品名，默认数量为 1，或使用“物品名称 x100”这种明确数量格式。

例如：

```text
Tritanium x1000
Pyerite x500
```

点击计算后，逐项检查名称、数量、参考单价、回收比例和小计。全部项目通过后才会显示可复制的完整合同金额；将金额复制到游戏内交给军团的合同中。网站不会代替玩家创建、接受合同或转账。

存在禁止回收、无法识别、缺少价格或无效项目时，显示的只是可回收部分小计，不能当成整张清单的合同金额复制。移除或修正问题行后重新计算，并确保合同内物品和最终报价一致。

每次计算保存价格和规则快照。成员可以查看自己的最近报价，管理员可以核对本站成员的报价。规则后来改变不会改写旧报价；报价到期后需要重新计算。

## 价格与识别边界

- 物品目录来自 [EVE 官方静态数据](https://developers.eveonline.com/docs/services/static-data/)，支持精确中英文名称；搜索可以模糊匹配，但正式报价不会猜测相似物品。
- 市场基准使用吉他 4-4 空间站挂单：最高买单或最低卖单。中间价必须同时存在两侧行情，没有一侧时不拿另一侧冒充中间价。
- 行情有缓存和更新时间，不代表立即成交保证，也不按整批数量模拟挂单深度。军团实际愿意支付的金额由管理员设置的规则决定。
- 没有市场行情的普通物品可以由管理员配置固定价；接口失败或缺价不会按零元处理。
- 蓝图原图与副本、突变装备等特殊属性无法只靠普通物品名安全估值，需要人工核对；此计算器不自动估算研究等级、剩余流程、装配、容器内部或突变属性的价值。未复制到清单中的物品不会自动加入报价。
- 当前目录是随本次发布固定的版本，更新游戏物品后可重新生成并发布。生成脚本是 `scripts/generate-buyback-catalog.mjs`，输入官方 JSONL SDE 压缩包路径。

## 单军团运行

网站只接纳已配置的本站军团，不再为其他军团自动开通网站、创建管理成员或分配首位管理员。正常登录应使用本站军团角色；外军小号需要在已登录的本站账户中通过角色绑定入口加入。

成员、FC、管理员、总监、身份组专属权限及管理员配置的模块开关仍然有效。单军团不意味着任何 EVE 账号都能访问内部内容。

本站军团优先由 `PRIMARY_CORPORATION_ID` 指定；未配置时，只接受数据库中唯一且启用的主军团记录。不存在或存在歧义时拒绝访问，不猜测军团，也不会以首次登录者创建新站。

原有军团编号继续作为历史数据和外军小号资料的关联保留；不会删除、合并或公开旧军团数据。外军小号所需的军团资料引用不等于开通第二个站点。

## 维护验收

从仓库根目录运行 `pnpm --filter @workspace/api-server test:buyback` 和 `pnpm --filter @workspace/api-server test:single-corporation`。两组测试使用独立内存 PostgreSQL，不读取或写入生产数据库；其中 SSO 交互使用模拟 EVE 响应，不代表真实重新授权完成。发布前仍需运行 `pnpm install --frozen-lockfile`、`pnpm build`，并核对生产启动、健康检查及登录后界面。
