# 自动值守 PAP

自动值守 PAP 以管理员认可的游戏舰队和成员自身的参与证据为准，不要求舰队统帅属于本军团。网站不会控制游戏舰队，也不会读取外军团舰队统帅的全员名单。

## 启用顺序

1. 网站维护者在 EVE 开发者应用中允许以下只读权限：`esi-fleets.read_fleet.v1`、`esi-location.read_online.v1`、`esi-location.read_location.v1`、`esi-location.read_ship_type.v1`。沿用现有应用凭据和 SSO 回调，不新增环境变量；原有登录和技能授权不变。应用允许的权限与成员授权需同时满足，见 [EVE 官方 SSO 说明](https://developers.eveonline.com/docs/services/sso/)。
2. 管理员或总监打开总监区的「自动值守 PAP」，新建规则，填写实际游戏舰队编号、累计多少分钟发放一次、单次 PAP 数量、每人每天上限及 PAP 种类。可限制星系、舰种和未停靠状态。管理员本人加入目标舰队后，也可使用页面的当前舰队查询按钮取得编号。PAP 种类只使用现有种类或通用 PAP，不自动创建「值守 PAP」。
3. 新规则默认停用。核对后确认启用；编辑保存后也需要在页面上重新确认启用。同一游戏舰队只能有一条启用规则。舰队解散重建会产生新编号，需要重新认可，不能仅靠统帅名字匹配。
4. 成员打开「值守 PAP」，选择本人已经绑定且属于本军团的一个角色，点击「授权并启用采集」，在 EVE SSO 完成只读授权。每个主账号同一时间只采集一个角色，多角色不能叠加领取。
5. 成员查看当前采集状态、今日进度和自己的最近发放记录；管理员查看规则、成员采集状态和最近发放记录。舰队无需由网站 FC 创建。

上线本身不会创建规则、认可舰队、替成员授权或补发历史 PAP。管理员与总监以外的角色不能管理规则，网站 FC 权限也不自动等于管理权限。PAP 和舰队模块均需开启。

## 如何计时和发放

后台每轮完成后约 60 秒进行下一轮采集。只有角色在线、仍属于本军团、加入认可舰队且符合规则筛选的有效采样才参与计时。角色首次获得有效采样时只建立起点，不从舰队加入时间倒推。

连续两次有效、新鲜、同一规则版本的采样才累计间隔。间隔超过 150 秒不补算；单个间隔最多计入 90 秒。接口故障、缺少授权、离线、离队、禁止的停靠状态、星系或舰种不符以及重复缓存都不会作为在岗时间补入。短暂不符合条件会中断连续采样，已经累计的有效分钟仍保留在当天进度中。

达到规则的分钟门槛后自动入账。金额支持最多六位小数；每日上限按「主账号、规则、UTC 日期」计算，不是所有规则共用一个上限。如果最后一次完整金额会超过上限，仅发放剩余额度。UTC 零点开始新的一天，前一天未发放的分钟不结转。

成员暂停、重新授权、更换采集角色，以及管理员编辑或重新启用规则，都会重置相关未发放分钟和连续采样起点；已经发放的 PAP、每日已发金额和历史记录不会被重置。已有发放记录的规则不能更换 PAP 种类，需停用旧规则并新建，以免不同种类的金额混算。账号合并会保留发放历史并合并每日已发额度，暂停采集、丢弃未发放分钟，需要重新确认角色；不会把原账号的值守凭据转交给新账号。

发放与钱包、PAP 记录和审计记录在同一事务中提交。账户锁、规则版本、观测时间及唯一发放序号防止同一记录因重试、并行进程或重启重复入账。后台只采集本网站主军团的有效绑定成员；关闭模块后不再采集或发放。

## 可验证的边界

这些数据能验证账号角色的在线、舰队、位置、舰种和停靠状态，不能证明玩家一直在键盘前、正在听指挥或执行命令。若需要防止挂机，仍需额外的人工抽查或明确的签到机制，不能把「在线」当作人工行为证明。

ESI 的军团归属查询约有一小时缓存，角色实际离团到被外部接口确认可能存在延迟；网站已知的解绑、角色删除、成员归属变化和模块关闭会在发放前再次检查。数据过期或授权状态不确定时停止计时，不自动补算。缓存时限依据 [ESI 官方 OpenAPI](https://esi.evetech.net/meta/openapi.json)，并遵循 [官方缓存与限流建议](https://developers.eveonline.com/docs/services/esi/best-practices/)。

成员需实际完成新授权才能验证真实游戏采集。部署成功、模拟接口测试和未登录接口检查都不代表所有成员已经授权，也不代表真实角色已经获得 PAP。

## 上线验收

发布前验证：根目录 `pnpm install --frozen-lockfile`、`pnpm build` 通过；自动值守后端专项 60/60、前端专项 12/12、单军团与真实路由的合成 SSO 回归 28/28、既有 PAP 种类与钱包回归 25/25、配船 AI 回归 39/39 通过。数据库专项使用隔离的 PGlite，EVE 与 AI 请求均为测试替身，没有使用真实角色凭据或付费模型。

本机 `pnpm start` 已执行，但因未设置 `DATABASE_URL` 无法完成本地启动；生产启动、迁移和健康状态另行验证。构建保留了既有七处 UI sourcemap 提示，退出码为 0，不影响产物生成。

上线后首次使用，请先以明确认可的舰队及已授权角色验证状态变化和一次真实发放，再开放更多规则；不要为了测试手动修改生产钱包或补造参与记录。
